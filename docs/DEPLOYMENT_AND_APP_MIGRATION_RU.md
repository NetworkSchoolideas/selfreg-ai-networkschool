# SelfReg AI: развертывание и перенос прототипа в приложение

## Текущее состояние

- Публичный лендинг опубликован в репозитории `NetworkSchoolideas/selfreg-ai`.
- В корне лежит статический сайт: `index.html`, `styles.css`, `i18n.js`, `assets/`, `vercel.json`.
- Telegram-бот остается внутренним тестовым стендом. Основная целевая реализация для конкурса: веб-приложение, доступное через Vercel.
- Публичная ссылка на приложение должна оставаться одной; разделение ролей и доступ к внутренним экранам происходит уже внутри приложения.

## Импорт в Vercel

1. Открыть Vercel Dashboard.
2. Выбрать `Add New` -> `Project`.
3. Импортировать репозиторий `NetworkSchoolideas/selfreg-ai`.
4. Framework Preset: `Other`.
5. Build Command: оставить пустым.
6. Output Directory: оставить пустым.
7. Root Directory: корень репозитория.
8. Deploy.

После импорта Vercel будет автоматически пересобирать сайт при каждом push в `main`.

## Следующая техническая цель

Перенести Telegram-прототип в веб-приложение, не теряя модель саморегуляции:

- `bot.py` больше не должен быть основным продуктом, только тестовым стендом.
- Логика этапов, сценариев A/B, уточняющих вопросов и итоговой аналитики должна быть вынесена в отдельное ядро.
- Веб-интерфейс должен заменить команды Telegram: старт, выбор контекста, ответ подростка, уточнение, следующий шаг, финальная рекомендация.
- Кабинет педагога должен заменить Streamlit-дашборд: история ответов, фидбек ИИ, интерпретация по ученику, экспорт.
- Подключение LLM должно идти через провайдер-адаптер: GigaChat, OpenRouter, OpenAI/Vercel AI Gateway или mock-режим для демонстрации.

## Минимальная архитектура Vercel-версии

- `/` - лендинг проекта.
- `/student` - диалоговый интерфейс подростка.
- `/teacher` - педагогический кабинет.
- `/api/session` - создание и ведение сессии.
- `/api/respond` - обработка ответа и выбор следующего шага.
- `/api/student-summary` - итоговая аналитика для подростка.
- `/api/teacher-insight` - интерпретация данных для педагога.
- `/lib/selfreg-model` - модель этапов, сценариев A/B, fallback-логика.
- `/lib/llm-providers` - провайдеры ИИ и BYOK-подключение.

## Что важно сохранить из текущего прототипа

- Пятизвенная психологическая модель: цель, переход к действию, обратная связь, сличение, коррекция.
- Два сценария поддержки: A как дефицит/затруднение, B как избыток/перенапряжение.
- Снижение внешней поддержки: от подсказки к самостоятельности.
- Возможность неакадемического контекста: проект, спорт, творчество, отношения, работа, самоорганизация.
- Реакцию на непонимание вопроса: переформулировка без давления.
- Итоговый блок для подростка: что получилось, где была трудность, какой следующий шаг.

## Что нельзя тащить в production как есть

- Токены в коде.
- Глобальное отключение SSL.
- SQLite как единственную базу для публичного многопользовательского сервиса.
- Синхронные HTTP-запросы внутри асинхронной логики.
- Жесткую последовательность вопросов без связи с предыдущим ответом.

## Рекомендуемый первый спринт веб-прототипа

1. Создать Next.js/Vercel-приложение рядом с лендингом или заменить статический сайт на Next.js.
2. Вынести модель вопросов и сценариев в `lib/selfreg-model`.
3. Сделать mock-провайдер ИИ, чтобы приложение работало без ключей.
4. Добавить BYOK-настройку: пользователь может подключить GigaChat/OpenRouter ключ.
5. Реализовать `/student` с короткой сессией на 5 этапов.
6. Реализовать `/teacher` с чтением истории и кнопкой `Получить интерпретацию`.
7. После локальной проверки подключить реальный провайдер ИИ через env-переменные Vercel.
